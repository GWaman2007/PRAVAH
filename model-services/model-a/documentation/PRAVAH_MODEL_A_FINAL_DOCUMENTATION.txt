============================================================
1. OBJECTIVE
============================================================

PRAVAH Model A is an operational classifier intended to estimate
the likelihood of a documented future road-associated disruption
event for an observation at prediction time T.

The model is separate from the existing district-level regression
model.

The existing regression model remains unchanged.

Model A is NOT a thresholded version of the regression vulnerability
score.

============================================================
2. TARGET DEFINITION
============================================================

Target = 1:
A verified/documented road-associated disruption event occurs
within the defined prediction horizon after prediction time T.

Target = 0:
No documented event was present in the available event inventory
for the controlled negative observation.

IMPORTANT LIMITATION:

Target = 0 does not prove that a physical disruption did not occur.
It means that no corresponding documented event was available in
the finite event inventory under the negative-sampling procedure.

Therefore, the model should be described as estimating the likelihood
of a DOCUMENTED ROAD-ASSOCIATED EVENT rather than guaranteeing the
absence or presence of every physical road closure.

============================================================
3. DATASET CONSTRUCTION
============================================================

Positive event inventory:
28 exact-date road-associated landslide/disruption records.

Rainfall-complete positive prediction observations:
27.

Controlled negative observations:
56.

Total baseline observations:
83.

Positive/negative construction was performed using documented event
records and controlled negative sampling.

Negative observations were sampled from selected districts and were
excluded from a +/- 3 day window around documented events in the
same district.

The negative observations use representative district coordinates
where an actual road-level negative observation was unavailable.

This is an important limitation and should be stated in any
interpretation of Model A.

============================================================
4. PREDICTION-TIME ALIGNMENT
============================================================

For positive observations:

Prediction time T = event date - 1 day.

Features available only through T were used for the prediction.

This prevents information from after the event from entering the
prediction features.

Historical landslide exposure was calculated using only historical
records occurring before the prediction year.

============================================================
5. LEAKAGE CONTROLS
============================================================

The following leakage controls were applied:

1. Rainfall features use observations available through prediction
   time T.

2. Historical landslide counts use historical records only.

3. Post-disruption information was not used as a prediction feature.

4. The dataset was split chronologically rather than randomly.

5. The final model was frozen before the final reload and inference
   verification.

============================================================
7. FEATURES NOT INCLUDED IN BASELINE
============================================================

The following potential data sources were not included in the
baseline because adequate coverage/temporal alignment was not
available:

- Weather / forecast features
- Flood/water-level features
- Traffic features
- Live field evidence
- IIT landslide vulnerability raster

Water-level observations had insufficient same-day coverage and
large nearest-station distances.

The IIT raster had class-associated missingness:
coverage was available for positive observations but not for
negative observations, so it was excluded from the baseline rather
than introducing biased imputation.

============================================================
11. VALIDATION / TUNING
============================================================

Conservative XGBoost tuning was performed.

The tested configurations did not materially improve validation
performance.

The validation ROC-AUC remained approximately 0.45 for the baseline
and several alternative configurations.

Because the validation set contained only two positive observations,
no aggressive hyperparameter optimization was performed.

The baseline configuration was therefore retained and frozen.

13. FINAL TEST INTERPRETATION
============================================================

On the held-out chronological test observations, the frozen model
correctly classified 28 of 30 observations.

It identified 19 of 20 documented-event observations and correctly
identified 9 of 10 no-documented-event observations.

The model therefore demonstrated strong performance on this specific
held-out test sample.

However, the result should not be interpreted as production-level
generalization because the overall event dataset is small, the
validation set contains only two positive observations, and the
negative class is based on absence from the available documentation.

============================================================
15. INFERENCE FUNCTION
============================================================

A reusable inference function was created:

predict_pravah_model_a(observation, threshold=0.50)

The function:

1. Loads the frozen model.
2. Loads the frozen feature schema.
3. Validates all 17 required features.
4. Converts feature values to numeric form.
5. Rejects missing required values.
6. Generates an event probability.
7. Applies the configured classification threshold.
8. Returns the probability, prediction and interpretation.

============================================================
16. IMPORTANT MODEL LIMITATIONS
============================================================

1. Small dataset:
   Only 83 baseline observations were available.

2. Limited positive events:
   Only 27 positive observations were usable for the baseline.

3. Negative-label uncertainty:
   A negative label represents absence of a documented event rather
   than guaranteed physical absence of disruption.

4. Representative negative coordinates:
   Some negative observations use district representative
   coordinates instead of actual road-segment coordinates.

5. Limited validation sample:
   Only two positive observations are present in validation.

6. Limited spatial coverage:
   The event inventory and supporting datasets do not provide
   complete road-level coverage across Assam.

7. Missing live operational variables:
   Traffic, real-time field evidence, adequate water-level coverage,
   and forecast variables were not available at sufficient quality
   for the baseline.

8. Test-set composition:
   The held-out test set contains 20 positives and 10 negatives,
   so the reported metrics should not be interpreted as population-
   level event prevalence or universal future performance.

============================================================
17. FUTURE DATA REQUIREMENTS
============================================================

For a stronger operational PRAVAH Model A, the highest-priority
improvements are:

1. Verified road/bridge disruption events with:
   - exact timestamp
   - exact coordinates
   - road/bridge stable ID
   - disruption type
   - severity
   - closure/open status
   - verification source

2. True non-event observations with adequate observation coverage.

3. Road-segment geometry and stable road IDs.

4. Better timestamped river/water-level coverage.

5. Traffic observations.

6. Weather and forecast observations aligned to prediction time.

7. Live field reports/evidence.

8. A substantially larger number of positive disruption events.
